## 3. 关键新发现(本回合逆向成果)

### 3.1 yz 验证码公式(替代顶象滑块)
```python
yztoken = md5("1sciq" + 十位时间戳 + "1")   # cookie: yztime=ztime; yzcount=1; yztoken=yztoken
```
验证:3 个样本 MATCH;2026-08-30 晚再次实测通过。等价捷径:`GET /lxapp.php?lx=<任意>` 收 Set-Cookie。
**影响:从此不再需要人工处理验证码;之前的"验证码 e982 / 让我来输"的流程全部废弃。**

### 3.2 scixue 的真实前置条件
- 纯服务端渲染,无轮询(全站无任务型 API);但**必须**:yz 三件套 + 登录 cookie(尤其 `dlzt`)+ 正确 Referer。
- 缺 `dlzt` 的特色症状:页面出现 PHP Notice `Undefined index: dlzt in scicook.php on line 25`,uname 为空——**没有这个 Notice 的"空 result"才是真无缓存**。这也是第一版工具判断失误的根因之一。

### 3.3 Wiley 机构共享链(本回合最大突破)
- 后端检测:OpenAlex 显示 `oa_status=bronze` 只是门槛提示;实际上对任何 Wiley 未缓存 DOI,scidown 都会吐 zxwileyq 签名链。
- 链路:zxwileyq 页 → `form#asder` POST `authenticateSharedSP`(共享机构凭证,免账号免密码)→ Wiley 登录态 → `fetch('/doi/pdfdirect/<DOI>',{credentials:'include'})`。
- 试运转费:整链在真实浏览器里 ~1 分钟;签名链 5 分钟过期,别提前抓。

### 3.4 lxgo/lxgodown 是半装饰品
- `lxgo.php?lx=<URL>` 对 `.opjc` 秒级短路(等于 lxapp);对普通 URL 生的"立即下载"按钮 → `lxgodown.php`,而 lxgodown 的异步任务永远"转存中"(IndexedDB 本地状态)。**别信排队,别等。**
- `wangpan/nlxdown.php`(离线下载大陆)解混淆后 fetch=0 XHR=0——纯前端假进度,进度条是表演。

### 3.5 网盘"离线文件"列表
- 每次成功 scixue 解析会向 console.php 登记一条(文件名=DOI,3000KB 占位)——这不是"下载成功"的证据,**只是请求记录**。点"下载"只会 alert"网盘文件已过期,请在解析页面直接取回本地"。

## 4. 失败路径档案(按轮次,全部亲测)

### 4.1 致命弯路
| 尝试 | 结果 | 教训 |
|---|---|---|
| 直接 GET scixue.php?doi=(无 Referer) | "请求信息有误" | 永远带 Referer 走完整链 |
| 不带 yz cookie 直访 | 302 verify.php 顶象滑块 | 或用公式,或先 lxapp |
| 带登录但漏 dlzt | Notice + 空结果(伪装成"未收录") | 分类表见 02 §4 |
| 网盘登录后找"秒传秒下" | 纯本地 IndexedDB,无在线库 | 别在 UI 上找真功能,逆向 JS 再下结论 |
| wangpan/top/wiley.php | 跳密码页→夸克网盘广告钩子 | 网盘"数据库入口"是引流,非下载通道 |
| helpcreat/helpadd 求助渠道 | 站方 5篇/天 + 明确禁止批量提交 | **不要自动化提交**,账号直接被封 |
| open-accessk.xyz 镜像 | 本网络连不上 | 别信镜像站 |
| lxgodown 异步代抓 | 永远转存中 | 见 3.4 |

### 4.2 每篇的尝试序列(负知识样例:181)
以 181 为例(完整链路细节见 docs/05 §7):
bban 两前缀 404/404 → zy9 403 → scixue 空 → sci-hub.jp 命中但**坏条目**(691260B JSTOR 无关论文)→ .red 同坏 → .ee/.ren 只给假代理 → Bing PII 搜索发现唯一正确拷贝在 sci-hub.st/uptodate/ → sci-hub.st 证书全球坏死 + 屏蔽数据中心(archive SPN 403 / jina 422 / codetabs 522 / allorigins 522 / curl -k 0B)→ Wayback CDX 无 → krishikosh/AGRIS/CORE/OpenAlex/Unpaywall/EPMC 无 → Scholar IP 风控 → **结论:死局,转人工**。
**教训:** 当各镜像返回字节级相同的无关 PDF → 立即判定共享库坏条目,停止所有 sci-hub 尝试;PII(如 S0041010121001872)是对的,坏的是映射表。

### 4.3 环境特性
- Google Scholar:IP 风控("unusual traffic",代理出口不一致)→ 不可用。
- Bing:代理污染时返回完全无关结果(查询"S0041010121001872"返回包追踪广告)——同查询必须重试/换 mkt,且以解码后的 `u=a1<base64>` 为准。
- CORE:Turnstile 可点过,但查询常 5xx。
- open-access.shop 区域封锁弹窗在**页面加载后**才出现,curl 抓到的是正常 HTML —— 以实际行为(Download 弹窗选项)为准,别被静态 HTML 迷惑。

## 5. 工具链补充教训(写回代码的改动)

1. `title_words()` 必须 **`.lower()`**——漏了会把正确题名判为 2/8 命中(拒收),还会把 #76 错配成 #17(入库)。本次完成第 2 次修复。
2. 收割守护必须加 **SHA-256 去重**——重复下载同一篇会把同一文献入两次库(实测 #11 是 #10 的 dup、#39 是 #06 dup)。
3. 会话 cookie 里 `dlzt/dltoken` 与"网盘登录"绑定,`wangpan/login.php` 登录即全站通;但 **helpall.php(多馆际互借)在新站系统,登录态不同步**。
4. 任何"取回本地"下来的文件,**文档里只有 down.sciokk.cn 能出字节**;lxgodown 返回的是 HTML 任务页。
