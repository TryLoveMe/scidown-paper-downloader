# 风控手册:如何不被封 / 被封了怎么办

> 核心哲学:**慢就是快**。这个生态宁可礼貌地失败,不要 hammer。
> 所有阈值均为 2026-08 实测经验值,网站可随时调整。

## 1. 三道防线

| 防线 | 位置 | 触发条件 | 表现 | 脚本能过吗 |
|---|---|---|---|---|
| Cloudflare | zy9 / beatport 等前端 | 脚本 TLS/行为指纹 | 403 + 5-6KB 挑战页 | curl 偶尔能过;真浏览器自动过 |
| 顶象滑块 | scidown verify.php | 高频请求 | 滑块人机验证 | 基本不能,人工拖 |
| IP 降级 | scidown 后端 | 持续高频 | scixue 正常返回但 a=""(静默) | 不能,只能等 |

## 2. 频率红线(实测)

```
scidown 解析请求:  ≥ 8-10 秒/次, 且每过一次滑块只信任 2-3 次解析
bban/zy9 下载:     ≥ 3 秒/次
批量任务:          ≤ 10 篇/次调用, 批间隔 ≥ 1 分钟
触发 verify.php:   立即停止脚本请求! 越试标记越重
```

## 3. 被标记的自救流程

1. **停**。删掉重试循环。IP 降级时重试解析只会得到空 `a`,还会加深标记。
2. 人工浏览器(用户的 Edge/Chrome)打开 scidown 正常点几单——真人流量会稀释标记。
3. 等待冷却(经验:几十分钟到数小时)。期间用「工作台+收割」模式继续干活:
   - 工作台 = 每篇文献两行固定模式直链(bban / zy9),人工浏览器逐个点;
   - 收割 = 脚本监控 ~/Downloads,题名核对后自动改名入库。
4. 冷却后再恢复脚本路线。

## 4. 人机分工原则

| 任务 | 谁做 | 原因 |
|---|---|---|
| bban 缓存直链下载 | 脚本 | 无任何防护 |
| zdwe 网关下载 | 脚本(curl) | 无 CF,但有签名时效 |
| scidown 登录图形验证码 | 有视觉的 AI 或人 | 4 位扭曲字符 |
| 顶象滑块 | **人** | 服务端校验轨迹,脚本过不了 |
| zy9 / 蓝奏云 | **人的浏览器** | CF/会话绑定,脚本不可行 |
| 题名核对/改名入库 | 脚本 | 规则化工作 |

## 5. 账号安全

- scidown 登录会话 ~30 分钟过期,正常现象,重登即可。
- 「记住密码」会把**明文密码**写进 cookie(`dlps=<密码>`)。分享 cookie 文件前务必清理。
- 登录图形验证码不区分大小写(实测),错了解码换一张即可。

## 6. 给 AI agent 的特别提醒

- 不要写"while not ok: retry"这种循环对付风控页——那是标记加深器。
- 看到 HTTP 200 但内容是 HTML/`a=""`,要**区分**"没这文献"和"我被降级了":前者如实报告,
  后者停手等冷却。
- 下载成功的唯一标准:`%PDF` 魔数 + 题名核对通过。错误页也是 200。
- 每篇文献记录来源路线(bb缓存/zy9/网关/人工),失败记录原因——用户会问"为什么这几篇不行"。
