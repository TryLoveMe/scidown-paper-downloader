# 风控手册:如何不被封 / 被封了怎么办

> 核心哲学:**慢就是快**。这个生态宁可礼貌地失败,不要 hammer。
> 所有阈值均为 2026-08 实测经验值,网站可随时调整。
> 本手册包含:风险层识别 → 频率红线 → 免验证通道 → 静默降级识别 → 自救流程 → 人机分工。

---

## 1. 风险层总览(从上到下,每一层都有"表现特征")

| # | 防线 | 位置 | 触发条件 | 表现(特征串) | 脚本能否最终解决 |
|---|---|---|---|---|---|
| 1 | Cloudflare | shop / zy9 / beatport / Wiley | TLS 指纹或行为评分 | 403 + 5-6KB 挑战页("Just a moment...") | curl 偶尔过;真浏览器自动过;Turnstile 复选框点一下即过 |
| 2 | Validate 页 | scixue.php 无 yz cookie | 未带 yz 三件套 | 302 → /verify.php(顶象) | **能**——yz token 可公式生成(§3) |
| 3 | 顶象滑块 | verify.php | 越过了第 2 层还高频 | 滑块"拖动还原" | **不要碰**——轨迹服务端校验,自动化成功率极低 |
| 4 | IP 降级 | scidown 后端 | 持续高频 / 多账号 | scixue **200 正常返回但 `a=""`**(静默!) | 不能,只能冷 |
| 5 | UA 白名单 | down.sciokk.cn | UA 不带 360 标记 | 403/拒绝 | 加 ` QIHU 360SE` 后缀即可 |
| 6 | 区域封锁 | shop + 92.223.124.29 | 中国大陆 IP | "Access is not supported in your region"/connection refused | 不能本地绕,必须走 scidown 中转链 |
| 7 | Referer 校验 | scixue/lxapp/scifree | 无 Referer 直访 | "友情提醒:请求信息有误"(340B) | **能**——带正确 Referer |
| 8 | 登录失效 | scixue | 会话过期/缺 dlzt | PHP Notice `Undefined index: dlzt` + uname 空 | **能**——补全 cookie;dlzt 是时间戳 |

## 2. 频率红线(实测)

```
scidown 解析请求:  ≥ 8-10 秒/次
bban/zy9 缓存下载: ≥ 3 秒/次
sci-hub 镜像访问:  ≥ 5 秒/次(部分镜像有 Cloudflare 配额)
批量任务:          ≤ 10 篇/次调用, 批间隔 ≥ 1 分钟
触发 verify.php:   立即停止脚本请求! 越试标记越重
```
- 每个 DOI 的完整解析链(如 lxapp→scixue→down1)也计为"请求",冷却按整链算。
- 网盘用户(Kevstah 院士)有每日离线配额,但**离线下载通道本身基本是装饰**(见 01 §2.7),别为配额而海量提交。

## 3. 免验证通道(2026-08-30 逆向成功,替代滑块)

### 3.1 方式 A:lxapp 白拿 yz cookie(推荐)
```bash
curl -s -c jar.txt "https://www.scidown.cn/lxapp.php?lx=http%3A%2F%2F92.223.124.29%2F<DOI>.opjc" -o /dev/null
# jar.txt 里现在有: yztime=<unix秒>; yzcount=1; yztoken=<md5>   (600s 有效)
```
### 3.2 方式 B:公式自算
```python
import time, hashlib
ztime = int(time.time())
yztoken = hashlib.md5(f"1sciq{ztime}1".encode()).hexdigest()
cookies = {"yztime": str(ztime), "yzcount": "1", "yztoken": yztoken}
```
- 3 个实测样本全部 MATCH;有效期 600 秒,超时重新生成即可,无需刷新页面。
- **不需要把页面上看到"滑块"当风险**——只有当你手工走 verify.php 流程(或故意不带 yz)才会弹出。

## 4. 静默降级(最难识别的风险)

- 表现:scixue 200,页面正常,但 `#uname` 为空 / `value=""`。**不报错。**
- 判别表:
  | `#uname` 值 | 含义 | 动作 |
  |---|---|---|
  | 空 + 页面有 PHP Notice dlzt | cookie 不全 | 补全登录 cookie 重试 |
  | 空 + 无 Notice + `a` 与 uname 均空 | 未收录(无缓存非 Wiley)或 **IP 降级** | 对照:换一个有缓存 DOI 复测 —— 它也空 = 降级;它有 = 真没这篇 |
  | `https://doi.org/<DOI>` | 主站无缓存(Elsevier 系回落) | 主站放弃,转 docs/05 离线源 |
  | 其他直链 | 正常 | 该干嘛干嘛 |
- 降级处理:**停**。删掉重试循环。人工浏览器正常点几单稀释标记;冷却几十分钟~数小时后再恢复脚本。

## 5. 被标记的自救流程

1. **停**。所有对 scidown 的脚本请求立刻停止(降级时重试只会加深)。
2. 人工浏览器打开 scidown 正常用——真人流量稀释标记。
3. 等待冷却(经验:几十分钟到数小时),期间用「工作台+收割」模式继续干活(§6)。
4. 冷却后小步恢复:先 1 篇试水,OK 再继续;再触发就再冷却。
5. 若怀疑 IP 被持续标记:换网络(手机热点 4G/5G IP 通常干净)。

## 6. 人机分工原则(工作台 + 收割模式)

| 任务 | 谁做 | 原因 |
|---|---|---|
| bban/缓存直链下载 | 脚本 | 无防护 |
| zdwe 网关直链下载 | 脚本(curl) | 无 CF,签名 ~1h |
| Wiley SharedSP 链 | AI + 浏览器(IAB) | 表单流程短,页面 fetch 可拿字节 |
| sci-hub Turnstile 复选框 | AI(坐标点击) | 点一下即过,无需人 |
| 顶象滑块 / 区域封锁页 | **人** | 轨迹校验/网络不可绕 |
| 登录图形验证码 | 有视觉的 AI 或人 | 4 位扭曲,canvas 导出可自读 |
| 蓝奏云 / zy9 CF 盾 | 人的浏览器 | 会话绑定/CF 行为评分 |
| 题名核对/改名入库 | 脚本 | 规则化 |

**工作台模式标准流程:**
1. 为每篇待下文献生成候选直链(bban/zy9/出版社/数据库直链),写 HTML 表格(编号/标题/DOI/按钮);
2. 用户默认浏览器打开,人逐篇点;CF 自动过;PDF 落 ~/Downloads;
3. `harvest_daemon.py` 监控 ~/Downloads:pdftotext 前两页 × 题名词命中(≥60%)→ 通过则按 `编号_作者_年份_标题.pdf` 改名入库;SHA-256 去重(重复下同一篇只入库一次);
4. 实测要点:文件名不可信(常见 21935.pdf 之类),**只认题名核对**;等文件写完(>10KB 且 2s 内大小稳定)再处理。

## 7. 账号安全

- scidown 登录会话约 30 分钟过期,正常;过期症状=scixue 又给 wangpan/login.php 表单或 uname 空。
- 「记住密码」会把**明文密码**写进 cookie(`dlus=<用户名>; dlps=<密码>`)。分享/提交 cookie 文件前务必清理。
- 图形验证码不区分大小写(实测),错了解码换一张即可。

## 8. 给 AI agent 的特别提醒

- 不要写 `while not ok: retry` 对付风控页——那是标记加深器。失败要先分类(§4 表),分类错了会污染判断。
- **HTTP 200 ≠ 成功**。错误页、挑战页、坏条目都是 200。唯一标准见 docs/01 §5(魔数+大小+题名核对)。
- 看到 PDF 字节但题名核对失败 → **丢弃并记录**(可能是坏条目);不要为了"完成任务"强行入库。
- 每篇文献记录来源路线(缓存/网关/镜像/Wayback/机构认证/人工),失败记录原因与证据——用户会追问"为什么这几篇不行"。
- 站方条款限制批量求助(helpadd 5篇/天,禁批量提交)——**不要自动提交求助表单**,那是把账号往封里送。
